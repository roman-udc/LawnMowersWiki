# Symptom-keyed generic Problem pages with shared Cause pages, not per-brand pages

The Sources are mostly written per brand ("Bad Boy won't start", "Ariens won't turn over", "bad Kawasaki starter solenoid"), but the wiki does not mirror that. Each Problem page is keyed by a symptom the way a customer reports it, and it is generic across brands; brand-specific detail lives in a "Brand notes" section. Causes get their own pages because the same Cause (dirty carburetor, bad solenoid) explains several Problems, and copying it into each Problem page would leave inconsistent copies. Symptom families that point to different Causes are split into separate Problems ("won't crank" vs "cranks but won't start" vs "starts then dies"), with aliases and "Not this problem?" links between siblings.

## Considered Options

- **Per-brand pages**: rejected. They would copy the duplication already in the Sources, and the support agent would have to cross-check dozens of pages that are almost the same.
- **Cause-only pages**: rejected. Customers report symptoms, not diagnoses, so the agent needs a symptom entry point.
- **One page per broad symptom ("won't start")**: rejected. It is too coarse, and the Diagnostic questions that tell sub-symptoms apart would get buried.
